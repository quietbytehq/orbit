## 1. App icon

- Done: the source icon had a white page background and a pale rim around the squircle. The shape
  is cut out by flood-filling the near-white background from the corners, eroded 7 px to drop the
  rim, anti-aliased, and placed on a transparent background with the gradient colour extended
  outward so downscaling never bleeds white. `tauri icon` regenerated `src-tauri/icons/`; the
  Android and iOS folders were removed; `static/favicon.png` is the new 64 px rendering.
- Verified: the 128 px rendering on a dark panel has no light border (inspected as an image);
  `assets/orbit-icon.png` is 1024×1024 RGBA with fully transparent corners.
- Not verified: the icon in a real Start menu, dock or title bar.

## 2. Splash

- Done: setting "Intro animation" = Full / Short / Off (v0.1's `splashEnabled: false` loads as
  Off). Full plays about 5.5 s, Short 1.5 s, both scaled proportionally from the 3.5 s base
  phases. The backend plays Full on the first launch of a new version (first install or update,
  tracked by `lastSplashVersion` in settings.json) and Short otherwise; the splash page asks the
  backend which to play before animating. Skip and the 0.3 s fade-out are unchanged.
- Verified: Rust tests for the migration and the plan rule; vitest for the timeline scaling;
  svelte-check; build.
- Not verified: the animation by eye.

## 3. Icons

- Done: `@lucide/svelte`, one icon module (`src/lib/icons`) fixing size 16 / stroke 1.75 (22 /
  1.6 on cards). Sidebar icons; toolbar buttons with icon + label that become icon-only with a
  tooltip below 720 px of toolbar width (container query); provider glyphs on storage and
  add-storage cards; file-type icons by extension (`fileKind`, tested); icons on the main actions
  of the backup, drives and overview pages.
- Verified: screenshots at 1100 px and 860 px (wide: labels, narrow: icons only); vitest for the
  extension map; svelte-check.
- Note: lucide has no brand marks, so each service gets a generic symbol (cloud, box, database,
  terminal, network).

## 4. Plain-language UI

- Done: every string lives in `src/lib/text/strings.ts` (built per platform; tests reject
  "remote", "mount", "rcd", "RC" and allow "rclone" only on the engine card and in Settings ›
  Advanced) and `src-tauri/src/text.rs`. On screen: Cloud storage, Backup & sync (Copy / Mirror),
  Drives (Windows: drive letter, File Explorer, This PC, "Show as drive", "Remove drive") or
  Folders (Linux). The platform comes from a new `app_info` command. Errors say what happened and
  what to do; raw text goes to `AppError.details` (also on failed checks, transfers and runs) and
  `ErrorNote` shows it behind "Show details". Storage-engine errors are mapped to plain
  explanations (not found, exists, sign-in, quota, network). Windows mounts default to a free
  drive letter (unchanged).
- Verified: Rust tests (text module, error serialization, connection-check message), vitest for
  the strings, svelte-check, screenshots with Windows and Linux wording.
- Not done: the add-storage wizard field labels and help stay with the form definitions in
  `remotes::providers` (documented as the one exception). Only English ships.
- Also fixed: a race in the job store where a finishing run and an edit could save at the same
  time and one rename failed (seen once as a flaky test).

## 5. Start at sign-in, remembered drives

- Done: `tauri-plugin-autostart` with a `--minimized` argument; a launch with it shows no splash
  and no main window. Setting "Start Orbit when I sign in" enables or disables the entry and is
  re-applied at every launch. `mounts.json` remembers every mount with "Connect this drive
  automatically when Orbit starts"; automatic ones reconnect once, the first time the engine is
  healthy. Disconnected entries are offered again with their last location and a Forget link.
- Verified: unit tests for the store, the restore selection and a corrupt file; svelte-check;
  screenshot of the dialog and the settings section; the crate builds on Linux and in CI on Windows.
- Not verified: the actual autostart entry on a real Windows or Linux session, and reconnection
  on a real desktop (no display here; the restore path is the same `mount` call the tested
  integration test uses).

## 6. Network share (SMB) wizard

- Done: provider "Network share (Windows/Samba)" on rclone's `smb` backend: server name or IP,
  share name (optional), username, password, domain (optional), port (445). The share is stored
  with the connection and used as the start path for the connection check and for Open.
- Verified: an integration test against real rclone creates the remote, checks the hidden
  password, the start path and that an unreachable server gives a plain message with details.
- Not verified: a real SMB server.

## 7. Size column

- Verified: the existing integration test checks that rclone's reported byte count reaches the
  UI for ordinary files; the mock screenshot shows sizes for ordinary files. Items rclone reports
  with size −1 (Google-native documents) show "—" with a tooltip explaining they are live
  documents, not files. Nothing was broken, so nothing was fixed.

## 8. Packaging

  "Orbit for rclone". Version bumped to 0.2.0.
- Verified: the rename script on a fake bundle tree; CI artifact names (see CI above).
